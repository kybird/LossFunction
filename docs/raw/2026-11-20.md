## Case 1: doc→docs 마이그레이션 — llm-wiki v0.10.0 레이아웃 계약 채택

### Grounding
- Git Context: `hash:2b7021f`(v0.10.0 템플릿 갱신) → `hash:1656e55`(마이그레이션) — 결정은 두 커밋 사이 워킹트리
- Evidence: v0.10.0 첫 명령 시 경고문 —
  "⚠ doc→docs 마이그레이션 보류 — docs/가 이미 있다. 수동으로 옮긴 뒤 doc/을 지우거나
  llm-wiki.config.json에 \"migrateDocDir\": false를 두어라."

### Design Decision
llm-wiki v0.10.0이 레이아웃 계약을 바꿨다: `docs/`(복수)가 문서 루트 정본, 레거시 `doc/`은 폴백.
이 레포는 docs/(credentials·architecture 등 5개 파일)가 이미 있어 자동 이동이 보류됐고,
CLI는 "둘 다 있으면 docs/ 기준으로 판정"한다 — 실제 지식베이스는 doc/에 있어 판정 기준과
실체가 어긋난 상태가 계속될 뻔했다. 오너 결정(2026-11-20): **거부(migrateDocDir: false) 대신
수동 마이그레이션 완료**를 택했다. 이유: 거부 시 CLI 내부 기준과 실제 트리가 영구히 어긋나고,
향후 v0.10.x 기능이 docs/ 경로를 전제할 때마다 수동 보정이 쌓인다.

실행 내역:
- `git mv doc/{kanban,wiki,raw} docs/` — 커밋 1656e55에서 전부 rename 추적 확인
- 살아있는 위키 페이지 10개의 구경로 표기 48건(`doc/raw`·`doc/wiki`·`doc/kanban`) → `docs/*` 정리
- AGENTS.md 자체 섹션(1-28행)·README 120-121행 경로 갱신 — 주입 섹션 내 "레거시 doc/" 언급 2곳은
  계약 설명이라 의도적으로 보존
- done/·abandoned/·raw 로그 내 역사적 경로 표기는 **보존**(당시 기록이지 살길이 아님)

### Analysis
- Why non-obvious: 주입된 AGENTS.md 섹션의 "레거시 doc/은 폴백이며 자동 마이그레이션된다"는
  문구와 달리, docs/가 존재하는 레포에서는 자동 이동이 보류됨 — 경고문을 직접 읽어야 안다.
- 검증: `llm-wiki lint` — "✅ No evidence violations (all hash refs and Error quotes found in
  raw logs)" + 링크 파손 0. `llm-wiki compile list`도 docs/raw/ 기준으로 정상 동작.
- 남은 자잘한 글: compile list가 6개 raw를 [unpromoted]로 표시(v0.10.0 신규 표시) — 페이지가
  이미 그 지식을 흡수했고 hash:로 근거 연결이 되어 있으므로 조치 불필요로 판단. v0.10.0의
  unpromoted 판정 기준은 페이지 본문 참조 방식과 어긋나는 것으로 보인다(별도 확인 과제 아님,
  경고 아닌 정보성 표시).

### Related Knowledge
- Concepts: [[deployment-operations]], [[docs-as-tests]]
- **Anti-Patterns**: 도구가 바꾼 레이아웃 계약을 "나중에" 처리 — CLI 판정 기준과 실체의 어긋남은
  조용히 쌓인다. 경고가 뜬 당일에 마이그레이션 완료.

## Case 3: 잠긴 금고로 백필 불가 문제 — 인터랙티브 암호 창 + 상태 파일 폴링 스킬화

### Grounding
- Git Context: `hash:632d2b7`(MLP 카드 완료 직후) → 워킹트리
- Artifact: scripts/dev/backfill-daily-agent.ps1, .agents/skills/kis-backfill/SKILL.md
- Confidence: 4/5

### Design Decision
에이전트 셸은 비대화형이라 잠긴 금고를 못 연다(backfill-daily.ps1의 가드:
"잠긴 금고 + 비대화형 실행 — 사용자 터미널에서 실행할 것."). 해법: **암호 입력만 사람 창으로
분리하고 실행·관측은 에이전트가 갖는다**. 래퍼(backfill-daily-agent.ps1)가 Start-Process로
띄운 보이는 콘솔에서 backfill-daily.ps1을 자식 프로세스로 돌리고, 종료코드를
data/backfill-status.txt(gitignored)에 쓴다. 에이전트는 그 파일만 폴링한다 — 시크릿은
사람 창의 마스킹 프롬프트→프로세스 트리 안에만 존재하고 상태 파일·에이전트 로그엔
시각·종료코드만 실린다. 절차를 kis-backfill 스킬로 문서화(AGENTS.md 표 갱신)해서
다음 세션에서 재사용한다.

### Alternatives Considered
- Option A: 사람이 자기 터미널에서 직접 실행 — 기각: 오너 부담이며 결과 회신이 입소문에
  의존한다. 에이전트가 완료를 검증·기록해야 한다(데이터 갱신 → 재학습 카드 판단).
- Option B: 암호를 에이전트가 전달받아 unlock — 기각: 시크릿이 채팅·프로세스 인자에
  남는다. 원칙 위반(키 값은 화면·파일·로그 출력 금지).
- Selected: 분리 창 + 상태 파일 — 사람은 암호만, 시크릿 경로는 기존 구조 그대로.

### Decision Code
```powershell
# scripts/dev/backfill-daily-agent.ps1 (요지)
& powershell -NoProfile -ExecutionPolicy Bypass -File (Join-Path $PSScriptRoot "backfill-daily.ps1") @RemainingArgs
$code = if ($null -ne $LASTEXITCODE) { $LASTEXITCODE } else { -1 }
Add-Content -Path $status -Value "exit=$code end=$(Get-Date -Format o)"
```

### Analysis
- Context: 금고 locked + 에이전트 비대화형 셸. backfill-daily.ps1은 원래 사람 터미널 전제.
- **Trade-offs**: 창이 떠 있는 동안 사용자 참석 필요 vs 시크릿 경로 무변경. 래퍼는 재시도
  안 함(90초 자동 재시도는 Rust 백필 내장 — 재실행 폭주 금지 규칙 보존).
- Reversibility: High — 래퍼·스킬만 추가, 기존 스크립트 무변경.

### Related Knowledge
- Concepts: [[vaultwarden-secrets]], [[mlp-pipeline]]
- **Anti-Patterns**: 비대화형 제약을 풀려고 시크릿을 에이전트 경로로 흘리기 — 제약을
  지키려면 입력 채널만 분리하면 된다.

## Case 5: 공식 저장소 대조 — 요청 형식 무결 확인, 토큰 디스크 캐시 패턴 발견

### Discovery
11-20 백필 500 원인 후보를 걷어내려 공식 샘플 저장소를 대조했다:

1. **요청 형식 완전 일치** — PATH(`/uapi/domestic-stock/v1/quotations/
   inquire-daily-itemchartprice`), TR_ID(FHKST03010100, 실전=모의 무접두), 쿼리 6개
   (FID_COND_MRKT_DIV_CODE=J, FID_INPUT_ISCD, FID_INPUT_DATE_1/2,
   FID_PERIOD_DIV_CODE=D, FID_ORG_ADJ_PRC), 헤더(authorization Bearer / appkey /
   appsecret / tr_id / custtype "P" / tr_cont) — 전부 우리 rust 구현과 동일.
   요청 결함으로 인한 500 가능성 제거.
2. **이슈 트래커는 사실상 미사용** — open 0 / closed 0, 공개 500 보고 없음.
3. **공식 토큰 캐시 패턴(우리와 다른 점)** — 공식 kis_auth.py는 토큰을 디스크(YAML,
   token+valid-date, 실전/모의 분리 파일)에 저장해 유효 기간 내 재사용:
   `read_token(svr)`은 `exp_dt > now_dt`일 때만 저장 토큰 반환, 아니면 재발급.
   공식 주석: "Token issued, validity period 1 day, if issued within 6 hours the
   existing token value is maintained, notification talk is always sent upon
   issuance." 우리 KisAuth는 프로세스 내 캐시만 있어 실행마다 tokenP를 호출한다.
4. README 비고: 모의계좌는 REST 한도가 낮아 무거운 호출은 실전 권장(EGW00201) —
   우리는 이미 실전 도메인 사용 중.
5. README 트러블슈팅 3항목(토큰 오류→`ka.auth(svr=…)` 재발급·"1분당 1회 발급",
   설정 파일 오류→앱키/앱시크릿·계좌번호 형식, WS 'No close frame received'→HTS ID)은
   우리 실패 양상과 전부 불일치: 발급은 성공(16:25 알림톡)했고, 틀린 앱키로는 발급 자체가
   안 되며, 차트 API는 계좌번호를 안 쓰고, 백필은 WS를 안 쓴다. 기술적 발급 상한은
   1분당 1회(정책 권고가 1일 1회).

### Analysis
- Why non-obvious: 500 원인 탐색이 "요청이 틀렸나"에서 벗어나 서버 측으로 수렴됨.

## Case 6: tee 강화가 래퍼를 죽였다 — PS 5.1 네이티브 stderr 2>&1 포장 + EAP=Stop 즉사

### Grounding
- Git Context: `hash:d2f73fa`(가이드 대조 직후) → 워킹트리
- Evidence: scripts/dev/backfill-daily-agent.ps1, data/backfill-status.txt(start=18:05:28
  만 있고 exit= 없음), data/backfill-last-run.log(UTF-16 파편 2행), lossfunction.exe
  부재, candles 무변경
- Confidence: 5/5

### Error (3차 실행, 오너 창 원문)
```text
powershell.exe :     Finished `release` profile [optimized] target(s) in 0.25s
At D:\Project\LossFunction\scripts\dev\backfill-daily-agent.ps1:32 char:1
+ & powershell -NoProfile -ExecutionPolicy Bypass -File (Join-Path $PSS ...
+ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    + CategoryInfo          : NotSpecified: (    Finished `r...get(s) in 0.25s:String) [], RemoteException
    + FullyQualifiedErrorId : NativeCommandError
```

### Environment Context
- Packages: Windows PowerShell 5.1(래퍼 호스트), cargo 1.97.1(진행 상태를 stderr로 출력)
- Migration Issue: No

### Fix Code
```powershell
# PS 5.1: 2>&1 stderr → ErrorRecord 포장 → EAP=Stop 즉시 종료. 호출 구간만 EAP를
# 내리고 레코드를 문자열로 풀어 tee.
$ErrorActionPreference = "Continue"
& powershell ... @RemainingArgs 2>&1 |
    ForEach-Object {
        if ($_ -is [System.Management.Automation.ErrorRecord]) { "$($_.Exception.Message)" }
        else { "$_" }
    } |
    Tee-Object -FilePath $log
$ErrorActionPreference = "Stop"
```
부수 수정: Tee-Object가 PS5.1에서 UTF-16LE로 쓰는 로그를 종료 시 UTF-8로 정리.

### Analysis
- Root cause: cargo는 "Compiling/Finished" 진행 상태를 stderr로 낸다. 래퍼가 이를
  `2>&1 |`로 받는 순간 PS 5.1은 각 줄을 NativeCommandError ErrorRecord로 포장하고,
  래퍼의 `$ErrorActionPreference = "Stop"`이 첫 줄에서 파이프라인 전체를 종료 —
  백필 바이너리가 뜨기도 전에 사망. 1·2차 실행이 멀쩡했던 건 tee가 없어서다.
- Why non-obvious: "원문 보존하려고 tee 추가"가 정확히 실패 원문을 만든 상황을 죽였다.
  EAP=Stop은 래퍼 자체 cmdlet 보호용이었는데, 리다이렉션 경로에서는 네이티브 출력까지
  종료 트리거로 바뀐다.
- How it was fixed: 호출 구간만 EAP=Continue로 낮추고 ErrorRecord를 문자열로 언랩해
  tee — 콘솔·로그 전부 평문으로 흐른다. 프롬프트(Read-Host)는 자식 프로세스 호스트에
  직접 렌더되므로 암호 입력 UX 불변.
- 검증: 4차 실행에서 wrapper가 "Finished … 0.25s" stderr를 평문으로 통과시키고
  status 파일에 exit= 도달하는 것으로 확인(아래 실행 결과 참조).

### Related Knowledge
- Concepts: [[kis-api]], [[vaultwarden-secrets]]
- **Anti-Patterns**: PS 5.1에서 EAP=Stop 스코프 안에 네이티브 stderr를 2>&1로 엮기 —
  진행 상태 출력 한 줄이 스크립트를 죽인다. 리다이렉션 구간은 EAP 스코프를 분리할 것.
