## Case 1: Python 패키지 스캐폴드 설계 결정 (src layout + hatchling + optional-dependencies)

### Grounding
- Git Context: `hash:a79826d`
- Evidence: pyproject.toml, src/lossfunction/, tests/test_scaffold.py
- Confidence: 4/5

### Design Decision
LossFunction Python 패키지 기반을 다음과 같이 확정했다:
- **src layout** (`src/lossfunction/`) — cwd import 오염 방지, 테스트가 설치된 패키지를 검증
- **hatchling** build backend — 설정 최소, PEP 621 준수
- **dev 의존성은 `[project.optional-dependencies].dev`** — `pip install -e ".[dev]"`로 설치
- **ruff**로 lint+format 통합 (line-length 100, select: E/W/F/I/UP/B/SIM)
- **pytest** (testpaths=["tests"], addopts="-q")
- Python 하한 `>=3.11` (개발환경 3.13.5, OCI 배포 호환 고려)

### Alternatives Considered
- Option A: flat layout (`lossfunction/` 최상위) — cwd에서 미설치 상태로 import되어 테스트가 설치 상태를 검증 못 함. 기각.
- Option B: PEP 735 `[dependency-groups]` — 구형 pip에서 미지원, OCI 포함 환경 호환 리스크. 기각.
- Option C: setuptools — 동작하지만 pyproject 설정 장황. 기각.
- Selected: src layout + hatchling + optional-dependencies — 호환성과 검증 품질의 균형.

### Decision Code
```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "lossfunction"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = []

[project.optional-dependencies]
dev = ["pytest>=8.0", "ruff>=0.6"]
```

### Analysis
- Context: 오픈소스 공개 전제로 누구나 clone 후 `pip install -e ".[dev]"` && pytest로 도달해야 함.
- **Trade-offs**: optional-dependencies는 표준이 dependency-groups로 이동 중이지만 현재 최대 호환. 추후 pip 25.1+ 보편화 시 이전 가능.
- Reversibility: High — pyproject 한 곳에 집중됨.
