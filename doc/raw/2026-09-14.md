## Case 1: Python 패키지 스캐폴드 설계 결정 (src layout + hatchling + optional-dependencies)

### Grounding
- Git Context: `hash:a79826d`
- Evidence: pyproject.toml, src/lossfunction/, tests/test_scaffold.py
- Confidence: 4/5

### Design Decision
LossFunction Python 패키지 기반을 다음과 같이 확정했다:
- **src layout** (`src/lossfunction/`) — cwd import 오염 방지, 테스트가 설치된 패키지를 검증
- **hatchling** build backend — 설정 최소, PEP 621 준수
- **dev 의존성은 `[project.optional-dependencies].dev`** — `pip install -e ".[dev]"`로 설치
- **ruff**로 lint+format 통합 (line-length 100, select: E/W/F/I/UP/B/SIM)
- **pytest** (testpaths=["tests"], addopts="-q")
- Python 하한 `>=3.11` (개발환경 3.13.5, OCI 배포 호환 고려)

### Alternatives Considered
- Option A: flat layout (`lossfunction/` 최상위) — cwd에서 미설치 상태로 import되어 테스트가 설치 상태를 검증 못 함. 기각.
- Option B: PEP 735 `[dependency-groups]` — 구형 pip에서 미지원, OCI 포함 환경 호환 리스크. 기각.
- Option C: setuptools — 동작하지만 pyproject 설정 장황. 기각.
- Selected: src layout + hatchling + optional-dependencies — 호환성과 검증 품질의 균형.

### Decision Code
```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "lossfunction"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = []

[project.optional-dependencies]
dev = ["pytest>=8.0", "ruff>=0.6"]
```

### Analysis
- Context: 오픈소스 공개 전제로 누구나 clone 후 `pip install -e ".[dev]"` && pytest로 도달해야 함.
- **Trade-offs**: optional-dependencies는 표준이 dependency-groups로 이동 중이지만 현재 최대 호환. 추후 pip 25.1+ 보편화 시 이전 가능.
- Reversibility: High — pyproject 한 곳에 집중됨.

### Verification
- `python -m venv .venv && pip install -e ".[dev]"` → `pip show lossfunction` Version: 0.1.0 확인
- `.venv/Scripts/python -c "import lossfunction"` → `import OK 0.1.0`
- `.venv/Scripts/python -m pytest` → `2 passed in 0.01s`
- `.venv/Scripts/python -m ruff check .` → `All checks passed!`
- 첫 커밋: `a79826d` (llm-wiki scaffold + Python base + kanban 21카드)

- Patterns: [[verify-by-install]]
- **Anti-Patterns**: flat layout에서의 미설치 import 통과 (테스트가 아무것도 증명 못 함)

## Case 2: Configuration 설계 — pydantic-settings + live 이중 확인 + .env.* 예외

### Grounding
- Git Context: `hash:8345787`
- Evidence: src/lossfunction/config/settings.py, tests/test_config.py, .env.example
- Confidence: 4/5

### Design Decision
- `pydantic-settings.BaseSettings`로 환경변수 + `.env` 파일 이중 로드, frozen 모델.
- `TradingMode` 기본값 PAPER. `trading_mode=live`는 `live_trading_confirmed=true`가
  없으면 settings 로드 시점에 `ValueError`로 거부 (아키텍처 문서 §5 원칙 구현).
- KIS 자격증명은 `SecretStr` — repr/model_dump에서 마스킹됨.
- `.gitignore`에 `.env`, `.env.*`, `!.env.example` — 템플릿만 추적.

### Alternatives Considered
- Option A: 순수 dataclass + os.environ 수동 파싱 — 의존 없지만 검증/변환 코드 전부
  수작성, 에러 메시지 품질 낮음. 기각.
- Option B: traitlets/dynaconf — 커뮤니티 표준성 부족. 기각.
- Selected: pydantic-settings — KIS 클라이언트/DB 카드에서도 타입 검증 재사용.

### Discovery
- `.env.example`이 `.env.*` 패턴에 매칭되어 커밋이 차단됨 → `!.env.example` 네거션
  필수. `.gitignore` 패턴 작성 시 템플릿 파일 예외를 잊기 쉽다.

### Verification
- `pytest` → `10 passed` (설정 로드/검증/마스킹/gitignore 가드 포함)
- `git check-ignore .env .env.local` → 무시 확인, `.env.example` → 추적 확인
- `ruff check` + `format --check` → 통과
