### Design Decision
과거 봉 조회를 `MarketDataSource` 트레이트(async daily_bars)로 정의, `Bar`(OHLCV,
완결 봉만)·`Timeframe`과 함께 `marketdata/` 모듈에 배치. 저장 계층은
`ON CONFLICT (symbol, timeframe, ts) DO UPDATE` 업서트 — 백필 재실행이 중복이 아니라
제자리 수정이 되도록. 모듈 의존은 공유 커널(types)뿐(증권사 모듈 무참조).

### Verification

- clippy 0, fmt 클린, marketdata의 `use crate::kis` 0건(grep)

### Analysis
- 2026-09-17 Case 1(라이브 봉 공급 부재)의 첫 해소 조각. 트레이트가 먼저임으로써
  카드 2(KIS 구현)가 코어를 오염시키지 않고 붙는다.
- 시간표기: 봉 타임스탬프 = 완결 순간(KST 15:30 = UTC 06:30), rfc3339 Secs로

## Case 2: KIS 기간별시세 스펙 실측 — tr_cont 없음, 호출당 100건 제한

### Grounding
- Git Context: `hash:5d65ab6`
- Evidence: 공식 샘플 저장소 koreainvestment/open-trading-api `examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py` + 공개 구현 교차검증
- Confidence: 5/5

### Discovery
국내주식기간별시세(일/주/월/년)[v1_국내주식-016] 스펙(샘플 원문 기준):
- GET `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice`
- tr_id `FHKST03010100` — **실전=모의 동일**(V prefix 없음)
- "실전계좌/모의계좌의 경우, **한 번의 호출에 최대 100건까지 확인 가능**"
- 파라미터: FID_COND_MRKT_DIV_CODE(J), FID_INPUT_ISCD, FID_INPUT_DATE_1/2
  (YYYYMMDD), FID_PERIOD_DIV_CODE(D/W/M/Y), FID_ORG_ADJ_PRC(0=수정주가)
- 응답: output1(메타) + output2(시세 배열). output2 행: stck_bsop_date,
  stck_oprc/hgpr/lwpr/clpr, acml_vol — 전부 문자열.
- 샘플이 tr_cont에 ""를 넘긴다 — **이 엔드포인트에는 tr_cont 페이지네이션이 없다.**
  장기 백필은 날짜창 분할이 정답(잔고의 ctx_area_fk100 방식과 다름).

### Analysis
- Why non-obvious: 프로젝트의 기존 REST 페이지네이션 지식(tr_cont M/F)을 이
  엔드포인트에도 적용하려다면 헛구현이 된다 — "조회 종료일자 (최대 100개)" 주석이
  계획 카드의 AC에도 잘못 반영됐을 만큼 헷갈리는 지점.
- Action taken: `kis/chart.rs` — 100달력일 비중복 창 순회(≈68거래봉/창, 상한 여유),
  만페이지(100행) 반환 시 재귀 대신 명시적 작업 스택으로 창 반분(depth 제한) —
  async fn은 boxing 없이 재귀 불가(E0733). rt_cd!=0은 기존 request()의 ApiReject로
  fail-loud. 가격은 수정주가 기본(권리락 간 지표 연속성).
- Verification: wiremock 4테스트(다중 창 병합 오름차순, 만페이지 반분, 비즈니스
  거부, 창 경계 트림). 전체 114 passed, clippy 0.
- **실증 대기 항목**: rest.rs request()가 `appkey` 헤더를 빈 문자열로 보낸다
  (`authorization`만 실값) — 공식 스펙은 모든 호출에 appkey/appsecret 헤더 요구.
  wiremock은 이를 못 잡는다. KIS 키 확보 후 실증 시 최우선 확인 포인트.
- 테스트 함정 기록: wiremock `.mount()`는 async — await 누락 시 목이 등록조차 안 돼
  404로 나타남(등록 실패라는 명시적 에러가 없음).

  연속 메커니즘이 다르다(tr_cont / 날짜창 / 단발)
